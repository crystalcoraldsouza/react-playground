## How npm updates dependency versions?

In package.json, the symbols `^` (caret) and `~` (tilde) are used to control how npm updates dependency versions.

They follow Semantic Versioning (SemVer):

> MAJOR.MINOR.PATCH <br/>
> 1.4.2

- MAJOR → breaking changes
- MINOR → new features (backward compatible)
- PATCH → bug fixes

### ^ (Caret)

Caret allows updates to minor and patch versions but not major versions.

### ~ (Tilde)

Tilde allows only patch updates.

### No Symbol

This locks the exact version. No automatic updates.

## What is package-lock.json?

`package-lock.json` is a file automatically generated by npm that locks the exact versions of all dependencies installed in a project.

It ensures that everyone installing the project gets the same dependency versions.

For example "react": "^18.2.0" allows npm to install 18.x.x. So different developers might get different versions. This causes "works on my machine" problems.

### Should you commit package-lock.json?

Yes! Always commit it to Git. It ensures consistent builds across machines and environments.

`integrity` is a cryptographic hash used to verify that the downloaded package has not been modified or corrupted. It ensures the package installed from npm is exactly the same as the one published. integrity is like a fingerprint of the package. If the fingerprint changes, npm knows something is wrong.

> "integrity": "sha512-abc123..."

#### When npm installs a package:

- It downloads the package from the registry
- Calculates its hash
- Compares it with the integrity value

If they match, installation continues.If they don't match, npm throws an error.

It protects against:

- corrupted downloads
- tampered packages
- malicious package replacements
- network errors

This adds security and reliability to dependency installation.

The integrity value usually looks like: `sha512-xxxxxxxx`. This means npm used the SHA-512 hashing algorithm to generate the checksum.

## What are Transitive Dependencies?

Transitive dependencies are dependencies of your dependencies.

They are packages that your project does not directly install, but are required by the packages you installed.

## Do we commit node modules to git?

No! You only have it where it is needed to run. You use gitignore for this.

## Do we commit package.json and package-lock.json to git?

Yes, you need to have both committed. Lock is needed to maintain the exact version on production.

## Hosting app with parcel

Parcel is a zero-config web application bundler—similar to Webpack or Vite—used to build, bundle, and serve frontend apps like React, HTML, CSS, and JavaScript project

> npx parcel index.html

### Parcel features

- Combines files (JS, CSS, images)
- Transpiles modern JS (e.g., JSX → JS)
- Optimizes assets
- Runs a development server
- HMR (Hot Module Replacement)
  - Updates only the changed part of your app without full reload
  - File watching algo in C++
  - Consistent hashing
- No need for config files (unlike Webpack)
- Works out of the box with:
  - React (JSX)
  - TypeScript
  - CSS/Sass
- Tracks imports and bundles everything correctly
- Fast Builds:
  - Uses caching for faster rebuilds
  - Only rebuilds what changed
- Code Splitting
  - Splits bundles automatically for performance
  - Loads only what’s needed
- Production Build
  - Minifies code
  - Optimizes images
  - Tree-shaking (removes unused code)
- Differential Bundling
  - New browsers → support ES6+ (fast, clean code)
  - Old browsers → need ES5 (transpiled, larger code, Includes polyfills)
  - dist
    - app.modern.js
    - app.legacy.js
- Better error handling
- Hosting HTTPs for testing
- Different environment bundles

| Feature     | Parcel  | Webpack | Vite      |
| ----------- | ------- | ------- | --------- |
| Config      | Zero    | Heavy   | Minimal   |
| HMR         | Yes     | Yes     | Very fast |
| Setup       | Easiest | Complex | Easy      |
| Build Speed | Fast    | Slower  | Fastest   |
